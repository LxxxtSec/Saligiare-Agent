# Saligiare 问题与解决记录

这份文档记录 Saligiare 开发过程中遇到的问题、排查过程、最终解决方案和可复用经验。
它既是故障记录，也是学习日志的一部分。

## 记录原则

1. 每个实际遇到的问题都记录，不只记录代码错误。
2. 记录事实、原因、解决步骤和经验，避免只写“已经修好”。
3. 不记录 API Key、Personal Access Token、密码、Cookie、目标凭证或其他秘密。
4. 命令可以记录，但要删除其中的敏感参数和真实路径中的隐私信息。
5. 问题解决后保留记录，不删除失败过程；失败过程有助于以后排查。
6. 每条记录使用唯一编号，方便在提交、Issue 和对话中引用。

## ISSUE-001：推送时报 `Repository not found`

### 现象

执行：

```bash
git push -u origin main
```

终端返回：

```text
remote: Repository not found.
fatal: repository 'https://github.com/LxxxtSec/Saligiare-Agent.git/' not found
```

### 排查过程

1. 检查远程地址是否写错。
2. 确认 GitHub 上是否真的存在目标仓库。
3. 确认当前账号是否有访问私有仓库的权限。
4. 注意 GitHub 对私有仓库的权限错误也可能返回这个提示。

### 原因

当时远程仓库尚未确认创建完成，且本地 GitHub 认证状态也没有确认。这个错误不能单独证明是 URL 错误，也不能单独证明是登录错误。

### 解决方法

先确认远程地址：

```bash
git remote -v
```

然后在浏览器中用目标 GitHub 账号确认仓库存在，最后使用有效的 GitHub Token 完成推送。

### 可复用经验

遇到 `Repository not found` 时，按这个顺序检查：

```text
远程 URL
→ 仓库是否存在
→ 当前账号是否有权限
→ 本地凭证是否有效
```

## ISSUE-002：本地没有 `gh` 命令

### 现象

执行：

```bash
gh auth status
```

终端返回：

```text
zsh: command not found: gh
```

### 原因

GitHub CLI 没有安装。`gh` 是可选客户端，不是 Git 推送的必要依赖。

### 解决方法

没有安装 `gh` 时，仍然可以使用普通 Git 加 HTTPS Personal Access Token 完成推送：

```bash
git push -u origin main
```

如果以后需要安装 GitHub CLI，再单独安装并执行：

```bash
gh auth status
```

### 可复用经验

区分：

- `git`：版本控制和远程推送的基础工具。
- `gh`：GitHub 的辅助命令行客户端。

缺少 `gh` 不等于 GitHub 不能使用。

## ISSUE-003：重复添加 `origin`

### 现象

执行：

```bash
git remote add origin https://github.com/LxxxtSec/Saligiare-Agent.git
```

终端返回：

```text
error: remote origin already exists.
```

### 原因

本地仓库已经存在名为 `origin` 的远程地址。`git remote add` 只能新增一个没有同名的远程。

### 正确处理

先查看：

```bash
git remote -v
```

地址错误时修改：

```bash
git remote set-url origin https://github.com/LxxxtSec/Saligiare-Agent.git
```

只有确实要删除再重建时才使用：

```bash
git remote remove origin
git remote add origin https://github.com/LxxxtSec/Saligiare-Agent.git
```

### 可复用经验

`remote add` 是“新增”，`remote set-url` 是“修改已有地址”。遇到重复添加错误时，不要重复执行 `add`。

## ISSUE-004：Git 提交身份与 GitHub 登录身份混淆

### 现象

执行：

```bash
git config user.name
```

输出了：

```text
beizishaozi
```

### 原因

`git config user.name` 只记录 commit 的作者名称，不负责 GitHub 认证。它可以和 GitHub 用户名不同，因此不能用它判断当前终端登录了哪个 GitHub 账号。

### 正确处理

为当前仓库设置提交身份：

```bash
git config --local user.name "LxxxtSec"
git config --local user.email "你的 GitHub 验证邮箱"
```

查看当前仓库配置：

```bash
git config --local --list
```

如果要修正尚未推送的最后一次提交作者：

```bash
git commit --amend --reset-author --no-edit
```

### 可复用经验

必须区分两种身份：

```text
Git commit 作者信息 != GitHub 远程认证凭证
```

## ISSUE-005：GitHub 不支持使用账户密码推送

### 现象

输入 GitHub 用户名后，在 Password 位置输入账户密码，返回：

```text
remote: Invalid username or token. Password authentication is not supported for Git operations.
fatal: Authentication failed
```

### 原因

GitHub 已经不允许使用账户登录密码进行 HTTPS Git 操作。

### 解决方法

使用 Personal Access Token 作为 Password：

```text
Username: GitHub 用户名
Password: Personal Access Token
```

Token 需要只授予目标仓库必要的 Contents 读写权限。Token 只在生成时保存到安全位置，不放进命令、文档或代码。

如果 macOS 缓存了错误凭证，可以清除 GitHub 的钥匙串凭证后重新认证：

```bash
printf "protocol=https\nhost=github.com\n\n" | git credential-osxkeychain erase
```

### 可复用经验

终端提示 `Password` 时，HTTPS Git 场景下通常应输入 Token，而不是 GitHub 登录密码。输入 Token 时终端不显示字符是正常现象。

## ISSUE-006：`.DS_Store` 成为未跟踪文件

### 现象

执行：

```bash
git status --short --branch
```

看到：

```text
## main...origin/main
?? .DS_Store
```

### 原因

macOS Finder 自动生成 `.DS_Store`，它不是项目源文件，也不应该提交到仓库。

### 解决方法

在仓库根目录的 `.gitignore` 中加入：

```gitignore
.DS_Store
```

然后提交忽略规则：

```bash
git add .gitignore
git commit -m "chore: 添加 Git 忽略规则"
git push
```

### 可复用经验

看到 `??` 时先用 `git status --short` 确认文件内容和来源，不要习惯性执行 `git add .`。

## ISSUE-007：`pyproject.toml` 的 Ruff 配置和终端行尾显示引起误判

### 现象

初次填写 `pyproject.toml` 时，Ruff 配置行写成了类似下面的形式：

```toml
target-version = ["py311"]
```

并且终端输出看起来像是行尾有一个 `%`：

```text
target-version = "py311"%
```

### 原因

`target-version` 应该是单个字符串值：

```toml
target-version = "py311"
```

终端显示的 `%` 不是文件内容，而是 zsh 在命令输出没有换行时显示的提示符。通过字节检查可以确认文件最后实际包含换行：

```bash
tail -c 40 pyproject.toml | od -An -t x1c
tail -n 4 pyproject.toml | sed -n l
```

### 解决方法

将配置调整为：

```toml
[tool.ruff]
line-length = 100
target-version = "py311"
```

使用 Python 内置的 `tomllib` 验证：

```bash
python3 -c 'import tomllib; tomllib.load(open("pyproject.toml", "rb")); print("pyproject.toml 语法正确")'
```

### 验证证据

终端输出：

```text
pyproject.toml 语法正确
```

字节检查显示文件最后一行以换行符结束，行尾没有 `%` 字符。

### 可复用经验

- 配置文件中的值类型很重要：字符串、数组和数字不能混用。
- 看到终端行尾的特殊字符时，先判断它是否来自 Shell 提示符。
- 使用解析器验证语法，使用 `sed -n l` 或字节检查验证不可见字符。
